### 2026-09-20 S0 契约 v2 评审反馈修订

已完成：按 M1/M2/M3/M6 在 PR #26 的评审反馈完成 packages/contracts/learning/ 下 6 份契约与对应 samples 的修订。

关键修订点（对应评审条目）：
- **课程与班级分离**：新增 `classId`（可空）落在 `Assignment` / `Submission` 上；新增 `Class` 资源概念。`Course` 本身不带 `classId`（见 courses.md:60、homework.md:15/65、README.md:74-75）。样例 02/03/04 的 `assignmentStudentView` / `assignmentTeacherView` / `submissionResponse` 已在 `courseId` 之后补 `classId`。
- **StudentSummary + graded 过滤**：教师列表 `GET /api/v1/assignments/{id}/submissions` 响应项组合 `studentSummary`（`studentId` + `name` + `studentNumber`，不进表避免姓名漂移），新增 `graded=true|false` 过滤（用 `gradedAt` 是否非 null 作判据，不用 `isCorrect=null` 猜）。
- **idempotencyKey 生命周期**：明确写入 `submissions` 表与响应体；同 key 重试返回 200 已有对象而非 201。
- **尚未提交改 200 + null**：`GET /api/v1/assignments/{id}/submissions/me` 无提交时返回 `{ "submission": null }`，不再 404。`SUBMISSION_NOT_FOUND` 只用于越权访问他人提交（见 errors.md）。
- **gradedBy 移出请求体**：批阅端点 `PATCH /api/v1/submissions/{id}/grading` 只接受 `isCorrect` / `score`；`gradedBy` 由服务端按会话角色推导写入（`teacher` / `auto` / `ai_assisted`）。样例 03 的 `gradingPatchRequest_teacher` 已删 `gradedBy` 字段。
- **tutoring_question 题型**：`Mistake.questionType` 区分来源——作业场景复用 `single_choice` / `multiple_choice` / `fill_blank` / `short_answer` / `proof`；答疑场景自由文本用 `tutoring_question`。样例 05 保持 `short_answer`（作业场景从答疑后标记但有 `assignmentId`）。
- **chapterId 由 M5 填、M3 传 null**：`planSuggestion.items[].chapterId` 一律 `null`（章节是 M5 域，M3 不生成 M5 域 ID），M5 保存时按 `knowledgePoint` 解析填入 `PlanItem.chapterId`。样例 06 的 `m3_planSuggestion_fetched_by_m5` 两项 `chapterId` 改为 `null`，`response_201_study_plan` 的 `items[].chapterId` 保留有值并补 `knowledgePoint` 字段。
- **TUTORING_TURN_NOT_FOUND 改 404**：从「422 校验失败」小节移到「404 防枚举」小节；message 改为「导学建议来源不存在或无权访问」。避免让客户端用 422/404 差异枚举 turnId。
- **事件 isCorrect/score 标可选**：`learning-events.md` 字段表用 `?` 后缀标注可空（主观题提交时 `isCorrect`/`score` 为 null；只判对错题型 `score` 为 null；答疑场景 `assignmentId`/`chapterId` 为 null）。样例 07 顶部 `_note` 已补可选性说明。
- **所有 ID 改前缀 + 32 位小写 hex**：`course_` / `chapter_` / `assignment_` / `submission_` / `mistake_` / `plan_` / `plan_item_` / `reminder_` / `event_` / `turn_` / `idem_` / `req_` / `user_` / `class_` / `doc_` 均对齐为「前缀+32 位小写 hex」。样例 01—07 与 errors.md 全量刷新。
- **章节列表真分页**：`GET /api/v1/courses/{courseId}/chapters` 接受 `page` / `pageSize`，默认 `pageSize=50`、上限 100；样例 01 的 `chaptersListResponse.pageSize` 从 100 改为 50 并补 `_note`。
- **subject 展示名**：`courses.md` 补充 `subject` 取值说明与展示名映射（math → 数学）。
- **选课归属 M1 说明**：`courses.md` 注明学生—课程—班级关系由 M1 维护，M5 只在 service 层调用 M1 鉴权接口判定 `classId` 访问权。
- **清理失效状态**：删除契约中遗留的草稿态枚举、未用字段（如旧版 `submission_status` 等）。
