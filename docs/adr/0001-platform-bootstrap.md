## 决策与范围

延续现有 React/TypeScript/Vite + FastAPI + PostgreSQL 的建议。此次只落地 API 部分，保持模块化单体；前端和数据库环境的版本在对应任务中明确，尚未安装或启动。

API 使用 Python 3.12.14、uv 0.12.13，运行依赖通过 apps/api/uv.lock 锁定并保留包哈希。清单设置兼容范围，所有开发/CI 安装必须使用 --locked，禁止合并时隐式更新依赖。

本次实际解析版本：FastAPI 0.141.1、Uvicorn 0.53.0、Pydantic 2.13.5、Pytest 9.1.1、Ruff 0.16.7、Mypy 1.20.2。全量及传递依赖以 uv.lock 为准。依赖升级必须单独评审锁文件变化。

## 为什么先做这个切片

M3 已提交答疑契约但若干公共约定待确认。一个无业务数据的健康检查可以验证开发环境、HTTP 入口、请求追踪、CI，供团队确认工程基线，不依赖模型密钥或尚未批准的答疑参数。

/api/v1/health 是唯一已实现业务 API 路由（另有框架文档路由），只证明进程存活。它不代表数据库、模型或鉴权可用。启动默认绑定 127.0.0.1，用于本地开发。

## 公共约定与评审

[平台契约](../../packages/contracts/platform/README.md) 区分已实现的健康检查候选行为和待评审的实体 ID、身份/权限、错误结构。M3/M5 评审 ID，M2/M6 评审客户端使用，M4 评审媒体调用影响。不修改 M3 原有草案或宣称其争议已解决。

## 验证与限制

本地通过 locked 安装、Ruff 格式/Lint、Mypy、3 项测试；代码覆盖率 100% 仅针对 26 行骨架逻辑，不代表整个项目完成度。独立 Uvicorn 进程经实际 HTTP 请求返回 200，验证后关闭。

当前 TestClient 依赖产生 2 条上游弃用警告（httpx 与 anyio 别名）；测试仍通过，未隐藏警告。后续依赖维护任务处理兼容升级。

CI 以低权限运行，使用完整 SHA 固定 GitHub Actions，记录真实运行结果；是否设为 main 必需检查属于后续仓库治理任务，不能仅凭 workflow 文件声称保护已生效。
