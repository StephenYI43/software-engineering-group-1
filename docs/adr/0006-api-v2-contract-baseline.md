# ADR 0006 v2 统一接口候选基线

- 状态：提议，待相关提供方/消费者和非作者评审。
- 日期：2026-10-27。
- 任务：#80。

## 背景

已接受的项目v1使用camelCase和资源响应。老师提供的接口课程采用snake_case及code/message/data/trace_id封套，并要求破坏性变更升版本。本次用户授权直接补齐缺失设计，不能借此静默更改旧客户端、已合并规范或服务。

## 提议

保留v1运行和原有开发分支，新增独立/api/v2候选描述；v2按老师规范统一JSON、请求参数、错误/追踪和分页。204、二进制和SSE遵循各自协议；SSE每帧JSON采用封套。旧AvatarController不是HTTP协议，保留camelCase组件SDK，由M2适配。

设计源生成OpenAPI3.1.1、TypeScript、样例/目录与Postman集合。Python校验器固定openapi-spec-validator0.7.2并锁定传递依赖；它是开发验证工具，不改变后端运行框架。规范校验、JSON Schema样例/反例和生成一致性进入CI。类型声明不替代运行校验或ACL。

## 影响

本PR的v2全部design-only，不能作为线上已有路由；没有自动创建第二套数据库、鉴权或应用框架。M5继续拥有关系表/public service，M1维护actor、入口、metadata；迁移仍单链。新增入班申请/派生内容/考试持久化和事件2.0必须单独评审迁移，不把#79参考DDL当已满足新接口全部依赖。

## 未采用

不在原/api/v1路径突然包data或把字段改名；不同时接受两种命名来掩盖兼容问题；不把任意JSON、任意provider URL或客户端自报角色透传给服务端。也不为了本课程一次性改写所有成员业务代码。

## 接受与退役条件

提供方和调用方明确确认字段、错误、权限与实例，非作者Review通过后，才按小批次接实际路由/PG并进行真实联调。v1停用需迁移验收和团队批准的日期。本ADR未接受前不覆盖既有v1命名规范。
